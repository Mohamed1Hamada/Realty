# Realty Office — نظام إدارة مكاتب العقارات

نظام ويب متكامل لإدارة مكتب عقارات واحد: العقارات، العملاء، المتابعات، العقود، العمولات، والحسابات.
مبني بـ **React 19 + TypeScript + Tailwind CSS v4** و**Supabase** (PostgreSQL + Auth + Row Level Security).

---

## ✨ الوضعين

| الوضع | الوصف |
|---|---|
| **Demo** (الافتراضي) | بيانات تجريبية محفوظة في المتصفح — شغّال من غير أي إعداد، مناسب للعرض على العميل |
| **Live** | متصل بـ Supabase فعليًا مع صلاحيات حقيقية لكل موظف |

التبديل بينهم من ملف `.env` فقط — **من غير أي تغيير في الكود**.

## 📦 الوحدات

### 1. لوحة التحكم
مؤشرات لحظية (عقارات، عملاء، عقود، عمولات، صافي الربح)، رسم بياني للإيرادات والمصروفات لآخر ٦ شهور،
توزيع العقارات حسب النوع، ترتيب الموظفين بالعمولات، وآخر النشاطات.

### 2. العقارات
- 10 أنواع وحدات (شقة، دوبلكس، فيلا، ستوديو، أرض، محل، مكتب، عمارة، مخزن، مزرعة)
- بيع / إيجار مع فترة الإيجار (شهري / سنوي)
- 5 حالات: متاح، محجوز، مُباع، مُؤجر، موقوف
- بحث + تصفية (الغرض، النوع، الحالة، المنطقة، نطاق السعر)
- كود مرجعي تلقائي (`PR-1001`) وتصدير CSV

### 3. العملاء
قاعدة بيانات العملاء والملاك مع نوع العميل، المصدر، الميزانية، والموظف المسؤول.

### 4. المتابعات (Leads)
مراحل: جديد ← تم التواصل ← معاينة ← تفاوض ← تمت الصفقة / خسران.
زر "تحريك للمرحلة الجاية"، وتنبيه للمتابعات المتأخرة والنهاردة.

### 5. العقود
عقود بيع وإيجار مع حساب **العمولة تلقائيًا**، والمتبقي من التحصيل.
عند إتمام العقد تتحدّث حالة العقار (مُباع / مُؤجر) تلقائيًا، وتُسجَّل العمولة المسددة في دفتر الحسابات.

### 6. الحسابات (للمدير فقط)
دفتر إيرادات ومصروفات ببنود جاهزة، ملخص الشهر الحالي وكل الفترة، تصفية بالشهر والبند، وتصدير CSV.

### 7. الموظفين والصلاحيات (للمدير فقط)
حسابات بصلاحيات **مدير / موظف**، نسبة عمولة لكل موظف، وإجمالي صفقاته وعمولاته.

### 8. الإعدادات
بيانات المكتب، تبديل اللغة (عربي / English)، تغيير لون الهوية، حالة الاتصال، وإعادة تعيين البيانات التجريبية.

---

## 🔐 الصلاحيات

- **المدير**: يشوف ويعدّل كل حاجة + الحسابات + الموظفين.
- **الموظف**: يشوف بس العقارات والعملاء والمتابعات والعقود المرتبطة بيه.

الصلاحيات مطبقة في **مستويين**:
1. واجهة المستخدم (`src/lib/permissions.ts`)
2. قاعدة البيانات عن طريق **Row Level Security** (`supabase/schema.sql`) — يعني حتى لو حد تلاعب بالواجهة، القاعدة نفسها بترفض.

## 🗂 هيكل المشروع

```
realty-office/
├── src/
│   ├── auth/            # سياق تسجيل الدخول
│   ├── components/
│   │   ├── layout/      # الشريط الجانبي، الهيدر، بطاقات المؤشرات
│   │   └── ui/          # مكونات shadcn-style (أزرار، جداول، حوارات…)
│   ├── config/          # site.config.ts — هوية المكتب
│   ├── data/            # طبقة البيانات: demo store + supabase repos
│   ├── hooks/           # useAsync
│   ├── i18n/            # عربي / إنجليزي
│   ├── lib/             # supabase client، analytics، صلاحيات، أدوات
│   ├── pages/           # الصفحات
│   └── types/           # أنواع TypeScript المطابقة للجداول
├── supabase/
│   ├── schema.sql       # الجداول + العلاقات + RLS + Triggers + Storage
│   ├── relations.sql    # العلاقات الـ 12 لوحدها (لوحدها أو للتأكيد)
│   └── seed.sql         # بيانات تجريبية
├── docs/
│   ├── SETUP_SUPABASE_AR.md   # دليل الربط خطوة بخطوة
│   ├── RELATIONS_AR.md        # شرح العلاقات + استعلامات جاهزة
│   ├── erd.svg                # رسم خريطة الجداول
│   └── FEATURES_AR.md         # ورقة المميزات للبيع
└── .env.example
```
